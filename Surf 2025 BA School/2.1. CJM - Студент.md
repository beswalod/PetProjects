# 2.1. CJM - Студент

## 1. Определение проблемы
Студент тратит много времени на разрозненные каналы (чаты, сайт, деканат, «устные» источники), из-за чего теряет информацию, пропускает дедлайны и не видит статус своих обращений.

## 2. Ключевые потребности / функции пользователя
1. **NEED-1.1** Посмотреть расписание своей группы.
2. **NEED-1.2** Посмотреть новости и анонсы мероприятий.
3. **NEED-1.3** Подать заявку в администрацию и отследить её статус.
4. **NEED-1.4** Записаться на консультацию к преподавателю.
5. **NEED-1.5** Найти ответ в FAQ/ЧаВо.

---

## 3. Логическая CJM: действия → сущности → переходы состояний

> В рамках CJM считаем, что пользователь уже авторизован.

### 3.1. Расписание

| № | Этап взаимодействия | Действие пользователя | Сущности | Переходы состояний |
|---|---|---|---|---|
| 1 | Открыть экран расписания | Переходит в раздел «Расписание» | Экран расписания, Профиль студента | `Экран: idle → loading → loaded` |
| 2 | Выбрать фильтры | Выбирает группу/дату/неделю | Параметры фильтра, Группа, День расписания | `Фильтр: default → selected` |
| 3 | Получить список занятий | Просматривает пары на выбранный день | Занятие, Преподаватель, Аудитория | `День: loading → loaded` |
| 4 | Открыть занятие | Нажимает на конкретную пару | Карточка занятия | `Карточка: collapsed → opened` |

### 3.2. Новости и мероприятия

| № | Этап взаимодействия | Действие пользователя | Сущности | Переходы состояний |
|---|---|---|---|---|
| 1 | Открыть ленту | Заходит в раздел «Новости» | Лента, Пост | `Лента: idle → loading → loaded` |
| 2 | Открыть пост | Читает полный текст и детали | Пост, Вложение, Ссылка | `Пост: preview → full_view` |
| 3 | Реакция на пост | Ставит лайк / комментарий | Реакция, Комментарий | `Реакция: none → liked`; `Комментарий: draft → published` |
| 4 | Участие в мероприятии | Нажимает «Хочу участвовать» | Мероприятие, Заявка на участие | `Участие: not_registered → pending/confirmed` |

### 3.3. Заявки в администрацию

| № | Этап взаимодействия | Действие пользователя | Сущности | Переходы состояний |
|---|---|---|---|---|
| 1 | Открыть раздел заявок | Переходит в help-desk | Экран заявок, Список заявок | `Экран: idle → loaded` |
| 2 | Создать заявку | Выбирает тип, заполняет форму, прикладывает файл | Заявка, Категория заявки, Вложение | `Заявка: draft → submitted` |
| 3 | Отслеживать статус | Просматривает карточку заявки | Заявка, История статусов | `submitted → in_review → approved/rejected/completed` |
| 4 | Уточнить заявку | Отправляет комментарий/документ | Комментарий, Вложение | `Комментарий: draft → published` |
| 5 | Закрыть обращение | Подтверждает, что вопрос решён | Заявка, Оценка качества | `completed → closed` |

### 3.4. Консультации

| № | Этап взаимодействия | Действие пользователя | Сущности | Переходы состояний |
|---|---|---|---|---|
| 1 | Открыть календарь консультаций | Переходит в раздел «Консультации» | Экран консультаций, Слоты преподавателя | `Экран: idle → loading → loaded` |
| 2 | Выбрать преподавателя/слот | Смотрит свободные окна | Преподаватель, Слот времени | `Слот: available → reserved` |
| 3 | Подтвердить запись | Подтверждает бронь | Запись на консультацию | `Черновик записи → booked` |
| 4 | Отменить/перенести | Меняет решение до дедлайна | Запись на консультацию | `booked → cancelled/rescheduled` |
| 5 | Провести консультацию | Посещает встречу | Запись, Факт посещения | `booked → completed/no_show` |

### 3.5. FAQ / ЧаВо

| № | Этап взаимодействия | Действие пользователя | Сущности | Переходы состояний |
|---|---|---|---|---|
| 1 | Открыть базу знаний | Переходит в FAQ | Раздел FAQ, Статья FAQ | `Раздел: idle → loaded` |
| 2 | Найти ответ | Ищет по ключевым словам/категориям | Поисковый запрос, Результаты поиска | `Поиск: empty → results/no_results` |
| 3 | Оценить полезность | Нажимает «полезно/неполезно» | Оценка статьи | `Оценка: none → rated` |
| 4 | Создать заявку при отсутствии ответа | Переходит из FAQ в help-desk | Статья FAQ, Шаблон заявки | `no_results → create_ticket` |

## 4. State-модели по ключевым сущностям

### 4.1. Заявка (Ticket)

```text
draft → submitted → in_review → (waiting_for_student | waiting_for_department)
      → (approved | rejected | completed) → closed
```

Правила:
- `draft` доступен только студенту.
- После `submitted` заявка фиксируется в журнале обращений.
- В `waiting_for_student` срок SLA может быть приостановлен.
- `closed` — финальное состояние.

### 4.2. Запись на консультацию (ConsultationBooking)

```text
created → booked → (rescheduled | cancelled | completed | no_show)
rescheduled → booked
```

Правила:
- `created` существует только до подтверждения.
- При `cancelled` слот снова становится `available`.
- `completed` и `no_show` — финальные состояния.

### 4.3. Пост/мероприятие (Post/Event)

```text
draft → moderation → published → archived
                └──────→ rejected
```

Правила:
- В `published` разрешены реакции и комментарии.
- `archived` недоступен для новых реакций, но остаётся в истории.

### 4.4. Слот консультации (TeacherSlot)

```text
planned → available → reserved → (occupied | released)
```

Правила:
- `released` возвращает слот в `available` при повторном открытии окна.
- `occupied` наступает в момент факта консультации.
